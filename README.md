# 客户经理工作台 — 旧版演示基线

本项目是纯前端教学应用。所有客户均为明确标注的虚构样例，不接银行系统，不含真实客户资料。

## 当前能做什么

- 查看 6 位虚构客户的列表与详情。
- 按客户名称、演示编号搜索，按企业/个人类型筛选。
- 使用地址 hash 切换客户详情，窄屏可返回列表。
- 展示基线版本与构建 commit。

**当前没有客户跟进提醒功能。** 本仓库为后续需求讨论、设计、编码、独立测试与受控发布提供旧版底座。没有故意制造缺陷。

## 本地运行

需要 Node.js（构建与测试使用标准库，无第三方 npm 依赖）。

```sh
npm run build
npm test
python3 -m http.server 4173 --bind 127.0.0.1 --directory public
```

打开 http://127.0.0.1:4173 。也可以直接打开 workbench.html；未构建源码中的 commit 为构建占位，不表示已提交或已部署。

## 文件

- `workbench.html`：自包含页面，HTML/CSS/JavaScript 均在文件内。
- `build.mjs`：生成 `public/index.html` 和 `public/version.json`，只发布此目录。
- `test-baseline.mjs`：基线静态契约检查，不代替浏览器行为测试。
- `vercel.json`：静态输出配置，禁止 Git push 自动触发部署。

## 数据边界

当前只读档案不写任何用户数据。后续跟进功能仅使用当前浏览器、当前 origin 的本地存储：刷新保留；换浏览器、设备、域名或部署 URL 不共享；清除浏览器数据后丢失。部署到新地址不会自动带走旧地址的数据。不要填写真实个人或企业资料。

不接 SQLite、Neon、Turso 或其他数据库；没有服务端持久化、SSO、短信或真实通知。

## 分支与发布边界

- `main`：旧版基线。
- `fact-demo/followup-reminder`：后续跟进提醒实现，确认需求和设计后才开发。
- 当前云部署暂停：不因推送代码或任务验收而自动创建 Vercel 项目、部署、推广、回退或变更套餐。
- 恢复发布后，先确认目标账户、项目、使用资格和权限，以测试过的确定 commit 构建候选，再验证并批准推广；不可拿分支最新内容替代测试版本。
- 固定域名推广与回退是代码版本切换，不会回退浏览器本地数据。持久化结构变更必须向后兼容。

## 验证

`npm test` 检查代码结构、虚构数据、基线不含新功能、构建产物和自动部署关闭配置。正式功能交付还必须运行针对候选版本的浏览器测试，不得将基线测试通过当作跟进提醒验收通过。
