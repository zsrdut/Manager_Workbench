# 客户经理工作台 — 客户跟进提醒演示

本项目是纯前端教学应用。所有客户均为明确标注的虚构样例，不接银行系统，不含真实客户资料。

## 当前能做什么

- 查看 6 位虚构客户的列表与详情。
- 按客户名称、演示编号搜索，按企业/个人类型筛选。
- 使用地址 hash 切换客户详情，窄屏可返回列表。
- 在客户详情新增带日期的跟进事项，并编辑、完成、撤销完成或删除已有记录。
- 在“我的工作台”查看全部客户的“今日待跟进”和“已逾期”事项；逾期区固定在上方，并显示“已逾期”文字徽标。
- 刷新或重开同一浏览器同一 origin 的页面后保留记录与完成状态。
- 展示版本与构建 commit。

## 本地运行

需要 Node.js（构建与测试使用标准库，无第三方 npm 依赖）。

```sh
npm run build
npm test
python3 -m http.server 4173 --bind 127.0.0.1 --directory public
```

打开 http://127.0.0.1:4173 。请使用 http origin 验收本地存储，不要用 `file://`。未构建源码中的 commit 为构建占位，不表示已提交或已部署。

## 文件

- `workbench.html`：自包含页面，HTML/CSS/JavaScript 均在文件内。
- `build.mjs`：生成 `public/index.html` 和 `public/version.json`，只发布此目录。
- `test-baseline.mjs`：基线结构、客户数据、构建与发布保护契约。
- `test-followup.mjs`：日期校验、存储编解码与失败路径、最小 DOM 桩下的渲染和操作流测试。
- `vercel.json`：静态输出配置，禁止 Git push 自动触发部署。

## 数据与存储

跟进记录只使用当前浏览器、当前 origin（协议 + 主机 + 端口）的 `localStorage`，键为 `manager-workbench.followups.v1`，值为带 `version: 1` 的信封。刷新保留；换浏览器、设备、域名或端口不共享；清除浏览器数据后丢失。部署到新地址不会自动带走旧地址的数据。不要填写真实个人或企业资料。

存储被禁用、配额不足、JSON 损坏或版本未知时，界面会明确提示并保留原输入；失败不会显示“保存成功”。损坏数据不会自动覆盖，需用户显式确认后才可清除。

不接 SQLite、Neon、Turso 或其他数据库；没有服务端持久化、SSO、短信或真实通知。

## 分支与发布边界

- `main`：旧版基线。
- `fact-demo/followup-reminder`：客户跟进提醒实现。
- 当前云部署暂停：不因推送代码或任务验收而自动创建 Vercel 项目、部署、推广、回退或变更套餐。
- 恢复发布后，先确认目标账户、项目、使用资格和权限，以测试过的确定 commit 构建候选，再验证并批准推广；不可拿分支最新内容替代测试版本。
- 固定域名推广与回退是代码版本切换，不会回退浏览器本地数据。持久化结构变更必须向后兼容。

## 验证

`npm test` 运行基线契约和跟进功能测试，覆盖新增、分区、逾期顺序、完成/撤销、编辑、删除、客户隔离、非法输入、安全渲染与存储失败路径。正式功能交付还必须运行针对候选版本的浏览器测试，不得只把自动化测试通过当作功能验收。
